# 패치노트

## 2025-12-10

### 새로운 기능

#### 1. 데이터셋 삭제 및 수정 API 추가
- 데이터셋 삭제 API (`DELETE /api/v1/datasets/{dataset_id}`)가 추가되었습니다.
  - 데이터셋 삭제 시 다음 항목들이 함께 삭제됩니다:
    - 데이터베이스의 데이터셋 레코드
    - 데이터베이스의 데이터셋 레지스트리 레코드
    - MLflow에 저장된 run 및 artifacts
    - S3에 저장된 데이터셋 파일들
  - 삭제 작업은 원자적으로 수행되며, 중간에 실패하면 모든 변경사항이 롤백됩니다.
- 데이터셋 수정 API (`PUT /api/v1/datasets/{dataset_id}`)가 추가되었습니다.
  - 데이터셋의 이름(`name`)과 설명(`description`)을 수정할 수 있습니다.
  - 수정하지 않을 필드는 요청에서 생략하면 됩니다.

### 개선 사항

#### 2. 워크플로우 삭제 및 정리 API 개선
- 워크플로우 삭제 완료 확인 API (`POST /api/v1/workflows/{workflow_id}/finalize-deletion`)에서 `run_id` 쿼리 파라미터가 제거되었습니다.
  - 이제 `workflow_id`만으로 호출할 수 있습니다.
  - Kubernetes 리소스를 직접 조회하여 삭제 여부를 확인하는 방식으로 변경되었습니다.
- 워크플로우 정리 완료 확인 API (`POST /api/v1/workflows/{workflow_id}/finalize-cleanup`)에서 `run_id` 쿼리 파라미터가 제거되었습니다.
  - 이제 `workflow_id`만으로 호출할 수 있습니다.
  - Kubernetes 리소스를 직접 조회하여 정리 여부를 확인하는 방식으로 변경되었습니다.

#### 3. 학습 상태 조회 API 개선
- 학습 상태 조회 API (`GET /api/v1/pipeline/training/{experiment_id}/status`) 응답에 `elapsed_time` 필드가 추가되었습니다.
  - `elapsed_time` (int): 경과시간 (초 단위, 자연수)
  - `start_time`부터 `end_time`까지의 경과 시간
  - 학습 진행 중인 경우 현재까지의 경과 시간
  - 항상 0 이상의 정수값

### API 변경 사항

#### 변경된 엔드포인트

- `POST /api/v1/workflows/{workflow_id}/finalize-deletion`
  - `run_id` 쿼리 파라미터 제거
  - 이제 `workflow_id`만으로 호출 가능

- `POST /api/v1/workflows/{workflow_id}/finalize-cleanup`
  - `run_id` 쿼리 파라미터 제거
  - 이제 `workflow_id`만으로 호출 가능

- `GET /api/v1/pipeline/training/{experiment_id}/status`
  - 응답에 `elapsed_time` 필드 추가

#### 새로 추가된 엔드포인트

- `PUT /api/v1/datasets/{dataset_id}`
  - 데이터셋 정보 수정
  - 경로 파라미터: `dataset_id` (int) - 수정할 데이터셋 ID
  - 요청 바디: `DatasetUpdateSchema`
    - `name` (str, optional): 새로운 데이터셋 이름
    - `description` (str, optional): 새로운 데이터셋 설명
  - 응답: 수정된 데이터셋 정보 (DatasetReadSchema)

- `DELETE /api/v1/datasets/{dataset_id}`
  - 데이터셋 삭제
  - 경로 파라미터: `dataset_id` (int) - 삭제할 데이터셋 ID
  - 응답: `{ "success": true, "message": "데이터셋이 성공적으로 삭제되었습니다." }`
  - 데이터셋 삭제 시 MLflow artifacts와 S3 파일도 함께 삭제됨

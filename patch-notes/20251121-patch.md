# 패치노트

## 2025-11-21

### 새로운 기능

#### 1. Workflow에 KNOWLEDGE_BASE 컴포넌트 추가 지원
- Workflow 생성 시 `KNOWLEDGE_BASE` 컴포넌트를 추가할 수 있습니다.
- RAG(Retrieval-Augmented Generation) 워크플로우 구성을 지원합니다.

#### 2. KNOWLEDGE_BASE 및 MODEL 컴포넌트 설정 옵션 추가
- `KNOWLEDGE_BASE` 컴포넌트에 `knowledge_base_id` 설정이 가능합니다.
- `MODEL` 컴포넌트에 `prompt_id` 설정이 가능합니다.
- 이를 통해 지식베이스 검색 결과를 프롬프트에 자동으로 포함시킬 수 있습니다.

### 개선 사항

#### 3. Workflow 구성 검증 로직 강화
다음과 같은 검증 규칙이 추가되었습니다:

1. **KNOWLEDGE_BASE와 ODM MODEL 공존 제한**
   - `KNOWLEDGE_BASE` 컴포넌트는 ODM(Object Detection Model) 계열의 `MODEL` 컴포넌트와 동일한 워크플로우에서 공존할 수 없습니다.
   - RAG 워크플로우와 ML 워크플로우를 명확히 구분하기 위한 제한입니다.

2. **KNOWLEDGE_BASE 위치 제한**
   - `KNOWLEDGE_BASE` 컴포넌트는 `MODEL` 컴포넌트보다 뒤에 위치할 수 없습니다.
   - 모든 실행 경로에서 지식베이스 검색이 모델 실행 전에 완료되어야 합니다.

#### 4. Knowledge Base 생성 오류 수정
- Knowledge Base 생성 시 특정 파일 타입만 업로드 가능하도록 제한되었습니다.
- **지원 파일 타입**:
  - PDF: `.pdf`
  - Word: `.doc`, `.docx`
  - Excel: `.xls`, `.xlsx`
  - PowerPoint: `.ppt`, `.pptx`
  - CSV: `.csv`
- 지원되지 않는 파일 타입 업로드 시 오류가 발생합니다.

#### 5. 학습 API GPU 필수 검증 추가
- 학습 API (`POST /api/v1/pipeline/training`)에서 GPU 개수(`gpus`) 파라미터는 필수적으로 1개 이상으로 설정해야 합니다.
- GPU 개수가 0 이하인 경우 400 Bad Request 오류가 발생합니다.
- 오류 메시지: "GPU 개수는 필수적으로 1개 이상으로 설정해야 합니다."

#### 6. Workflow 배포 시 GPU 사용 옵션 추가
- Workflow 모델 서비스 배포 API (`POST /workflows/{workflow_id}/execute`)에서 GPU를 사용하려면 `parameters`에 `"gpu_enabled": true` 속성을 포함해야 합니다.
- 예시:
  ```json
  {
    "parameters": {
      "gpu_enabled": true
    }
  }
  ```
- `gpu_enabled`가 설정되지 않거나 `false`인 경우 CPU 모드로 배포됩니다.

#### 7. 학습 목록 삭제 기능 추가
- 학습 실험(Experiment) 삭제 API (`DELETE /api/v1/experiments/{experiment_id}`)가 추가되었습니다.
- 실험 삭제 시 다음 항목들이 함께 삭제됩니다:
  - 데이터베이스의 실험 레코드
  - MLflow artifacts
  - S3에 저장된 모델 아티팩트
- **주의**: 삭제된 실험은 복구할 수 없으므로 신중하게 사용하시기 바랍니다.

### 유의사항

#### 리소스 제약 사항 - 중요!!!!!!
현재 GPU 자원과 Memory 자원이 제한적이므로 다음 사항을 주의하시기 바랍니다:

1. **GPU 자원 제한**
   - GPU 자원이 필요한 학습(training) 작업과 workflow 배포를 포함하여 **총 1개의 GPU만 사용할 수 있습니다**.
   - Workflow 모델 배포에 GPU를 사용하였다면, 학습 작업이나 기타 workflow 배포에는 더 이상 GPU를 사용할 수 없습니다.
   - 동시에 여러 작업에서 GPU를 요청할 경우 리소스 부족으로 인한 오류가 발생할 수 있습니다.

2. **Memory 제약**
   - 파라미터 수가 20B가 넘어가는 Ollama LLM 모델에 대해서 CPU 모드로 로드 시 Worker-01과 Worker-02의 Memory가 부족하여 배포가 실패할 수 있습니다.
   - 대용량 LLM 모델의 경우 **GPU 모드로만 Workflow 배포가 가능**합니다.
   - CPU 모드 배포를 시도하기 전에 모델 크기를 확인하시기 바랍니다.

### API 변경 사항

#### 변경된 엔드포인트

- `POST /api/v1/pipeline/training`
  - `gpus` 파라미터: 필수, 1 이상의 값만 허용 (0 이하 시 400 오류)

- `POST /workflows/{workflow_id}/execute`
  - `parameters.gpu_enabled` (boolean, optional): GPU 사용 여부 설정

#### 새로 추가된 엔드포인트

- `DELETE /api/v1/experiments/{experiment_id}`
  - 학습 실험(Experiment) 삭제
  - 경로 파라미터: `experiment_id` (int) - 삭제할 실험 ID
  - 응답: `{ "message": "실험 {experiment_id}가 성공적으로 삭제되었습니다." }`
  - 실험 삭제 시 MLflow artifacts와 S3 object도 함께 삭제됨

#### 변경된 스키마

- Workflow 컴포넌트 스키마에 다음 필드 추가:
  - `knowledge_base_id` (int, optional): KNOWLEDGE_BASE 타입 컴포넌트의 Knowledge Base ID
  - `prompt_id` (int, optional): MODEL 타입 컴포넌트의 프롬프트 ID

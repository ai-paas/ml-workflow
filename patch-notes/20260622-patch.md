# 패치노트

## 2026-06-22

ESM2(`facebook/esm2_t6_8M_UR50D`, 의료·바이오 단백질 언어 모델) 파인튜닝/추론을 기존 YOLOX
파이프라인 위에 통합했습니다. 설계 상세는 `docs/fine-tuning-and-inference/README.md` 참고.

### 새로운 기능

#### 1. ESM2 단백질 분류 파인튜닝 / 추론 지원
- 학습 API `POST /api/v1/pipeline/training` 한 벌로 YOLOX(객체 감지) / ESM2(단백질 분류) 양쪽을 학습합니다.
  - 모델군은 모델 row 의 `format`/`repo_id` 로 자동 판별하며, 모델군에 맞지 않는 데이터셋이면 400 으로 거부합니다.
  - `train_eval` 컨테이너는 `--model_kind` 로 분기하여 YOLOX 는 기존 학습, ESM2 는 HuggingFace Trainer + LoRA 로 학습합니다.
- 추론(`predictor`)에 `transformers` 프레임워크가 추가되어 ESM2 LoRA 어댑터를 서빙합니다.
  - 입력은 이미지가 아니라 단백질 서열 dict 입니다: `{"epitope": "LPRRSGAAGA", "cdr3b": "CASSEGLLYEQYF"}`
  - 응답: `{"predictions": [{"label": 1, "score": 0.872, "probabilities": {"0": 0.128, "1": 0.872}}], "input_info": {...}}`
- ESM2 카탈로그 모델은 `POST /api/v1/models/auto-generate?model_key=facebook/esm2_t6_8M_UR50D` 로 수동 등록할 수 있습니다.

#### 2. 데이터셋 분류(kind) 도입
- `GET /api/v1/datasets/kinds` (신규): 데이터셋 유형 카탈로그(`object-detection` / `protein-classification`)를 반환합니다.
- `dataset` 테이블에 `kind` 컬럼이 추가되어, 데이터셋이 어느 모델군용인지 분류를 보관합니다.
- 모델 상세/목록 응답(`GET /api/v1/models`, `GET /api/v1/models/{id}`)에 `recommended_hparams` 가 추가되어,
  UI 가 학습 폼을 모델별 권장 하이퍼파라미터로 prefill 할 수 있습니다. 학습 불가 모델은 `{}` 입니다.

### API 변경 사항 (Breaking change)

#### 1. 실험 상세 응답의 하이퍼파라미터 구조 평탄화
- `GET /api/v1/experiments/{id}` 의 `hyperparameters[]` 가 `hyperparameter_type` 중첩 구조에서
  평탄 KV 구조로 변경되었습니다.
  - 변경 전: `{ "value": "5", "hyperparameter_type": { "param_name": "epochs", ... } }`
  - 변경 후: `{ "id": ..., "experiment_id": ..., "param_name": "epochs", "value": "5" }`
- `hyperparameter_type` 테이블이 제거되었습니다(코드 어디에서도 안 읽히던 죽은 카탈로그).

#### 2. 학습 파라미터 `lr0`/`lrf` → `learning_rate` 단일화
- `POST /api/v1/pipeline/training` 의 `lr0`, `lrf` 가 제거되고 `learning_rate` 하나로 통합되었습니다.
  - YOLOX 내부에서는 `basic_lr_per_img = learning_rate / batch_size` 로 환산하고,
    `min_lr_ratio` 는 상수(0.05)로 고정합니다.

#### 3. `POST /api/v1/pipeline/training` 요청 형식 변경 (multipart/form-data)
- JSON 바디 → `multipart/form-data` 로 변경되었습니다.
- 데이터셋 입력은 `dataset_id` **또는** `dataset_file`(요청 시점 ZIP 업로드) 중 **정확히 하나**(XOR)만 받습니다.
  - `dataset_file` 동반 시 `dataset_kind` 가 필수이며, 자동으로 새 `dataset` row 가 생성됩니다.
- 모든 학습 파라미터(`learning_rate`/`batch_size`/`epochs`/`weight_decay`/`save_period`/`gpus`)는 선택값이며,
  비어 있으면 `user → 모델별 권장값 → 시스템 기본값` 순으로 백필되어 실제 적용값만 기록됩니다.

#### 4. 데이터셋 검증/등록에 `dataset_kind` 필수화
- `POST /api/v1/datasets/validate`: `dataset_kind` (Form, 필수) 추가. 분류별 형식(COCO / TCR-Epitope CSV)을 검증합니다.
  - 형식 불충족은 200 + `is_valid=false`, 알 수 없는 `dataset_kind` 는 422.
- `POST /api/v1/datasets`: `dataset_kind` (Form, 필수) 추가. 사전 `validate` 통과값을 받아 `dataset.kind` 에 저장하며,
  본 API 는 ZIP 을 재검증하지 않습니다.
- `GET /api/v1/datasets`, `GET /api/v1/datasets/{id}` 응답 원소에 `kind` 필드가 추가됩니다(요청 형식은 불변).

### 데이터베이스 마이그레이션 (forward-only)

> 본 통합의 마이그레이션은 **forward-only** 입니다(`downgrade` 미구현). 배포 전 운영 측에서 기존
> `experiment` / `hyperparameter` 행(특히 `lr0`/`lrf` 기록분)을 정리하는 것을 전제로 합니다.

- `0037`: `hyperparameter` 에 `param_name` 컬럼 추가 + `(experiment_id, param_name)` 유니크 제약 추가,
  `hyperparameter_type_id` FK/컬럼 제거, `hyperparameter_type` 테이블 제거.
- `0038`: `dataset` 에 `kind` 컬럼(nullable) 추가.

마이그레이션 파일은 SQLAlchemy 모델 변경 후 `make alembic-autogen-file` 로 생성합니다(직접 작성 금지).
